# CR-001 — RECOVERY_ARGON2ID parallelism becomes a fixed constant of 1

- **Status:** **ACCEPTED** — owner ruling at the WP-02 S4b review, 2026-08-19.
- **Raised:** 2026-08-18, PR #15 §2, by the implementing agent (TRS-CONST-003).
- **Applied:** WP-02 slice S4c, this commit.
- **Register entry:** `crypto_protocol.RECOVERY_ARGON2ID`
- **Affected requirements:** SRS-ONB-007, SRS-DAT-004, TRS-CONST-002, TRS-CONST-003
- **ADRs:** ADR-003 (content-only RecoveryRecord), ADR-004 (constants frozen and generated)

## Change

`RECOVERY_ARGON2ID.parallelism` becomes a **fixed constant of 1**.
`parallelism_min` and `parallelism_max` are **removed entirely**. The field is
not overridable and carries no bounds — the same shape as `MAX_SKIP_PER_CHAIN`.

```
  "parallelism": 1,          "parallelism": 1,
  "parallelism_min": 1,  →   (removed)
  "parallelism_max": 4,      (removed)
```

## Rationale (owner text)

libsodium's `crypto_pwhash` exposes no multi-lane Argon2 entry point, and
libsodium is the binding on both mobile platforms, so any lane count above 1
describes a record no shipping platform can open. This is a **portability
floor**, deliberately the opposite shape of the S4a resource-ceiling rule: the
memory and time ceilings sit far *above* the register's tuning maxima so that a
later build's stronger record still opens on an older one, whereas this bound
sits at the only value any binding can execute and admits nothing else.

Bounds on this field were therefore describing a tuning range that does not
exist. A minimum of 1 is the value itself and a maximum of 4 is unreachable;
keeping either invites a future build to write a record its own users cannot
recover from. Removing them makes the register state the fact directly.

## What does not change

All three implementations already refuse `parallelism != 1`, and that
enforcement stays exactly as it is, together with its negative vectors — the
`inflation_parallelism_unsupported` case in
`test-vectors/crypto/recovery_record.json` and the equivalent Go, Java and
Swift assertions. The wire format is untouched: the header still carries a
one-byte lane count, because a record must declare the parameters it was
written with even when only one value is legal. A reader that stopped checking
the field would accept a two-lane record and then derive a one-lane key,
failing with an indistinguishable authentication error.

## Consequences

- `constants_hash` moves. Every golden vector embedding it is regenerated and
  the full protocol-conformance suite reruns (TRS-CONST-003).
- The generated symbols `RecoveryArgon2idParallelismMin` /
  `RecoveryArgon2idParallelismMax` (Go), `RECOVERY_ARGON2ID_PARALLELISM_MIN` /
  `_MAX` (Java) and `recoveryArgon2idParallelismMin` / `Max` (Swift) cease to
  exist. Four call sites referenced them, all in tests or comments asserting
  the relationship this CR dissolves; they are rewritten to compare the
  single-lane rule against `RECOVERY_ARGON2ID.parallelism` itself.
- `TestTheSingleLaneRuleStillCoversTheRegisterMinimum` guarded a register
  minimum that no longer exists. It is replaced by
  `TestTheRegisterAgreesWithTheSingleLaneRule`, which asserts the register's
  fixed value *is* the supported lane count — the invariant that still has
  content after this CR.
- `TestOnlyASingleLaneIsAccepted` previously swept 2..`parallelism_max`. It now
  sweeps 2, 4 and 255: the old ceiling, and the largest value the wire field
  can carry.
